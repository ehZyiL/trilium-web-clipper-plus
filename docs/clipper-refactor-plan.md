# Trilium Web Clipper Plus 剪藏功能重构计划

本文档记录网页剪藏功能的分阶段改造方案。方案参考了 `edgeever` 和 `lumina` 的扩展实现，同时保留当前项目的 Trilium 保存协议和浏览器扩展形态。

## 总体原则

- 先修复确定性缺陷，再调整用户界面和提取能力。
- 保留现有 Trilium 保存协议，最终产物继续使用 HTML 正文和图片附件。
- 每个阶段都保持可安装、可使用，并配套回归验证。
- 不直接整体复制参考项目；只吸收提取、状态反馈、样式和测试方面的成熟做法。
- Markdown 可作为中间转换或可选导出格式，暂不作为 Trilium 入库前提。

## 当前问题概览

当前扩展使用原生 JavaScript、Manifest V3 和 Readability，剪藏链路集中在 `content.js` 与 `background.js`：

1. 正文提取、选区处理、图片发现、截图区域和动态脚本加载耦合在内容脚本中。
2. Readability 结果没有独立的 HTML 规范化层，网站差异会直接影响 Trilium 中的阅读效果。
3. 图片下载失败后可能留下随机 ID 占位符，最终形成破图。
4. 自动剪藏和异步消息流程存在目标标签页丢失、未定义回调等可靠性问题。
5. Popup 是多个等权重按钮，缺少主操作、当前页面信息和清晰的处理中状态。
6. 设置页和提示组件仍使用较旧的布局与样式组织方式。

## P0：可靠性修复与测试基线

### 目标

先解决剪错页面、图片破损、异步报错和日期错误，建立后续重构可以依赖的测试基线。

### 实施方案

| 工作项 | 方案 |
| --- | --- |
| 建立测试基线 | 为普通文章、选区、代码、表格、懒加载图片建立 HTML fixture；同时保存当前输出快照和显式结构断言 |
| 修正日期 | 分别处理发布时间和修改时间；无效日期不应导致整篇保存失败 |
| 修复自动剪藏 | 使用 `tabs.onUpdated` 的 `tabId`，移除回调中未定义的 `sendResponse` |
| 串行化自动任务 | 引入按任务串行执行的剪藏队列；多个标签页同时命中规则时逐个处理，并与手动剪藏共享队列 |
| 固定任务目标 | 剪藏开始时记录 `tabId`、`windowId` 和 `sourceUrl`，后续注入、提取、保存和反馈都使用同一任务目标 |
| 修复脚本加载 | 根据发起消息的 `sender.tab.id` 注入资源，不再依赖当前激活标签页 |
| 修复图片降级 | 下载成功时使用附件引用；下载失败时恢复原始 URL，不留下随机 ID 占位符 |
| 校验图片响应 | 检查 HTTP 状态、响应类型、超时和文件大小 |
| 清理隐式全局 | 修复 `noteFound` 等未声明变量 |
| 整理任务结果 | 区分成功、部分成功和失败，避免异常被吞掉或重复通知 |
| 校验自动规则 | 保持已有通配符兼容，并正确处理正则特殊字符 |
| 处理非法规则 | 单条规则编译失败时跳过并记录，不影响其他规则和后续自动剪藏 |
| 清理无效命令 | 删除 `chrome.commands` 中没有对应 manifest 声明的 `saveTabs` 分支；保留 Popup 和消息入口 |

### 验收标准

- 后台标签页触发自动剪藏时，保存的是被更新的标签页。
- 多个标签页同时命中自动剪藏规则时，任务串行执行，不与手动剪藏抢占同一保存通道。
- 同一标签页和 URL 的重复事件不会重复创建笔记。
- 剪藏过程中切换标签页或窗口，不影响原任务目标。
- 图片返回 404、非图片内容或超时，不会留下随机占位符。
- 日期缺失或格式错误，不会导致整篇保存失败。
- 手动正文、选区、截图、链接笔记和标签页列表完成回归验证。
- 所有异步异常都能通过界面提示或日志定位。
- 非法自动规则只影响自身，并会留下可诊断记录。

### Fixture 验证方式

采用“快照 + 显式断言”双层验证：

- **快照层：**保存重构前的实际输出，便于比较 HTML 结构和内容变化。
- **断言层：**单独断言标题、正文、代码块、表格、图片、链接、作者和日期等关键字段。

快照用于发现意外变化，显式断言用于防止通过修改快照而掩盖内容退化。只有在确认变化符合预期后，才更新快照。

### 交付物

- 可靠性修复。
- 基础 HTML fixture。
- 浏览器 API 和 Trilium 响应 mock。
- P0 回归检查记录。

## P1：Popup 与设置页重构

### 目标

保留现有功能，让日常剪藏更直接，并让当前页面、连接状态和任务进度清晰可见。

### Popup 信息架构

```text
┌─────────────────────────────────┐
│ Logo  Trilium Clipper      设置 帮助 │
│ ● 已连接 · 当前实例               │
├─────────────────────────────────┤
│ 当前网页标题                     │
│ example.com                     │
│ 检测到选区 · 123 字               │
│                                 │
│ [        剪藏选区 / 剪藏正文      ] │
│ [ 切换剪藏范围 ]  [ 区域截图 ]     │
│                                 │
│ ▸ 更多操作                       │
│   可见区域截图                   │
│   保存链接与笔记                 │
│   保存当前窗口标签页             │
├─────────────────────────────────┤
│ 正在提取 / 正在保存 / 保存结果     │
│ ▸ 最近剪藏                       │
└─────────────────────────────────┘
```

### 实施方案

- 有选区时默认剪藏选区，无选区时默认剪藏正文，并允许显式切换范围。
- 显示标题、域名和选区字数，帮助用户确认操作对象。
- 保留“此页面已剪藏”的状态提示，并提供打开已有 Trilium 笔记的入口。
- 分别显示连接、提取、图片处理、保存和完成状态。
- 处理中禁用重复提交，成功后保留可打开 Trilium 笔记的入口。
- 截图、保存链接、保存标签页放入“更多操作”折叠区。
- 使用统一的颜色、字体、间距、圆角和按钮 token，支持系统明暗主题。
- 使用 Shadow DOM 隔离网页内 toast 和截图操作层。
- Popup 与内容脚本使用两个独立入口；Popup 不再加载 `content.js` 或其他内容脚本依赖。
- 补齐键盘焦点、按钮标签、状态播报和文字对比度。

### 设置页调整

| 分区 | 内容 |
| --- | --- |
| 连接配置 | 桌面端口、服务器地址、认证字段、连接测试 |
| 自动剪藏 | 规则列表、语法提示、URL 匹配预览 |
| 保存选项 | 现有保存选项及说明 |
| 外观与语言 | 系统/浅色/深色、中文/英文 |
| 诊断 | 最近错误和脱敏诊断信息 |

### 验收标准

- 原有剪藏、截图、链接笔记、标签页功能全部可达。
- 连接失败时可以直接重试或进入配置。
- 有选区、无选区和受限页面都有准确提示。
- 中英文、明暗主题和较长标题不溢出。
- 截图取消后页面操作层完整清除。

### 交付物

- 新版 Popup。
- 卡片式设置页。
- CSS token 和主题样式。
- Shadow DOM 提示组件。
- 更新后的中英文文案。

## P2：提取管线与站点适配

### 目标

提升正文完整度、图片处理质量和 Trilium 中的阅读效果，并用 fixture 证明改进有效。

### 统一提取管线

```text
固定任务目标
  → 采集元数据与选区
  → 选择提取策略
  → 站点 reader / Readability / 回退策略
  → HTML 语义清洗
  → 图片与链接归一化
  → 结果检查
  → 转换为现有 Trilium payload
```

### 建议模块

```text
content/
  capture.js              剪藏入口与策略调度
  selection.js            选区提取
  metadata.js             标题、作者、日期、来源
  normalize-html.js       HTML 清洗
  images.js               图片发现与 URL 处理
  readers/
    generic.js
    wechat.js
    juejin.js
    zhihu.js
```

### 实施方案

1. 先采集元数据，再选择候选正文节点；不能无条件取第一个 `article` 或 `main`。
2. 通用提取使用 Readability，并保留正文过短时的合理回退。
3. 使用标签和属性白名单清洗 HTML，保留代码、表格、图片、引用、列表和有效锚点。
4. 删除事件属性、危险内容、无效样式和空包装，不默认执行 HTML 到 Markdown 再转回 HTML。
5. 识别懒加载图片、`currentSrc` 和 `srcset`，按解析后的 URL 去重并限制下载并发。
6. 优先实现微信、掘金和知乎 reader，每个 reader 都提供匹配条件、清理规则、失败回退和 fixture。
7. 使用同一组 fixture 对比 Readability 和 Defuddle，再决定是否引入构建链和新依赖。

### 验收标准

- fixture 能验证标题、正文、代码、表格、图片和链接。
- 清洗结果不包含脚本、事件属性和危险 URL。
- 显式选区模式失败时，不静默改为保存全文。
- 正文过短或疑似提取失败时，有明确提示并尝试合理回退。
- 在 Trilium 中实际验证代码、表格、图片和链接显示效果。
- 引擎替换有对比结果，不能只依赖主观判断。

### 交付物

- 模块化提取管线。
- 首批站点 reader。
- 扩充后的 fixture 和检查脚本。
- Readability/Defuddle 对比结果。

### 当前实现记录（P2 第一版）

当前版本在不改变 MV3 和 Trilium HTML 入库协议的前提下完成了 P2 的第一轮实现：

- `content/metadata.js` 读取 meta、`time` 和 JSON-LD 中的标题、作者和日期。
- `content/normalize-html.js` 使用标签和属性白名单清洗正文，移除脚本、事件属性、危险链接和无效样式，并处理懒加载图片。
- `content/readers.js` 提供微信、掘金、知乎、少数派、Medium、Substack、Substack Note、GitHub、YouTube 和 Bilibili，以及参考项目中的 Hacker News、V2EX、豆瓣、雪球、BOSS、小宇宙、即刻、Facebook、Instagram、LinkedIn、Threads 和 Bluesky reader。
- `content/capture.js` 统一执行站点 reader → Readability → 候选正文回退，并返回现有 HTML payload 所需的正文节点。
- `content/capture.js` 为正文输出附带 `good`、`partial`、`low` 质量级别；低于阈值时返回 `short-content` 警告，便于界面提示和诊断。
- `tests/p2-pipeline.test.mjs` 对站点 reader、危险 HTML、懒加载图片、JSON-LD 和 Readability 回退执行 DOM fixture 测试。
- `tests/compare-extractors.mjs` 使用同一批 fixture 对比当前管线、Readability 和 Defuddle，结果保存到 `tests/fixtures/p2-extractor-comparison.json`。
- `tests/live-site-smoke.mjs` 对公开的掘金、少数派、GitHub、V2EX、YouTube 和 Bilibili 页面执行真实网络 smoke 验证。

Defuddle 只作为开发期对比依赖，没有打入扩展运行时。当前 8 个 fixture 均能由三种引擎提取正文，当前管线的正文长度均不低于 Readability 和 Defuddle；因此保留现有零构建运行时，并把 Defuddle 留在可重复的 A/B 验证工具中。

## P3：本地暂存与编辑（可选）

### 目标

支持离线剪藏、保存前整理和失败重试。

### 实施方案

- 使用 IndexedDB 保存正文、资源和任务状态。
- 增加独立暂存箱页面，支持标题、正文和来源编辑。
- 区分草稿、待发送、发送中、失败和已发送状态。
- 失败时保留内容，重试时尽量避免重复创建笔记。
- 增加容量上限、清理策略和手动删除入口。
- 先实现失败任务保留与手动重试，再评估完整编辑器。

### 验收标准

- 关闭 Popup 或重启浏览器后，已暂存内容仍然存在。
- Trilium 离线时可以暂存，恢复后可以手动发送。
- 配额不足、图片过大或发送中断时不会静默丢失内容。
- 重试和重复点击不会轻易生成重复笔记。

## 推荐执行顺序

第一轮实施 **P0 + P1**：先让剪藏稳定、界面清晰，同时收集失败网页作为 P2 的验收样本。

第二轮实施 **P2**：根据真实失败样本改进通用提取和站点适配，不提前引入不必要的构建链。

第三轮再根据使用反馈决定是否实施 **P3 暂存箱**。

每个阶段完成后都应保留一个可安装版本，并记录新增依赖、兼容性变化、测试结果和已知限制。
